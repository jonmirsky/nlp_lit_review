1. SYSTEM PURPOSE (ONE PARAGRAPH)
---------------------------------
This pipeline maintains a living systematic-review catalog for an NLP
literature review project. For each configured PubMed query it: (1) fetches
or accepts RIS bibliographic records, (2) attempts full-text PDF download via
Selenium (V4 scraper), (3) stores PDFs in a content-addressable Google Drive
folder (and mirrors to Cloudflare R2), (4) stamps each record with a search-
term label in the RIS `RN` field, (5) merges new records into the visualizer's
master RIS under visualizer_nlp_lit_review/RIS_source_files/, and (6) records
every run in a timestamped folder with auditable metadata. The Flask
"visualizer" web app reads that master RIS to render query/branch flowcharts,
overlap stats, and PDF links.

4. ENTRY POINTS (HOW WORK IS STARTED)
-------------------------------------

A) Single search (recommended CLI):
   python3 automated_search/scripts/auto_search_wrapper.py \
     --query '<PubMed query>' \
     --slug nlp_extraction \
     --label '( NLP extraction )'

B) Batch all catalog searches:
   python3 automated_search/scripts/refresh_catalog.py
   (--dry-run, --continue-on-error supported)

C) Desktop admin (no Flask required):
   python3 admin_gui.py
   - "Search and Pull": one wrapper run (catalog + optional extra AND terms)
   - "Refresh Catalog": refresh_catalog.py
   - "Stop": SIGTERM to process group (see §12)

D) Flask admin (local only, ADMIN_ENABLED=true):
   visualizer_nlp_lit_review/app.py routes /admin, /api/run_search, etc.
   NOT enabled on production Render deploy.

E) Resume interrupted scrape:
   python3 automated_search/scripts/auto_search_wrapper.py \
     --resume automated_search/searches/<run_id>


5. PIPELINE STAGES (DETAILED)
-----------------------------

STAGE 0 — Bootstrap (search_run.bootstrap_search_run)
  - Allocates automated_search/searches/YYYY_MM_DD_HHMMSS__<slug>/
  - Collision suffix -2, -3, ... if folder exists
  - Writes metadata.json (atomic write via save_metadata)
  - Creates found/, missing/, progress/errors/log paths
  - query_source determines next step:
      entrez        → fetch PubMed via Bio.Entrez → input.ris
      manual_export → copy --input-ris → input.ris
      byo_found_ris → skip V4; use --found-ris as found/found.ris

STAGE 1 — Entrez fetch (if query_source == entrez)
  - Requires: NCBI_EMAIL (ToS), optional NCBI_API_KEY
  - SSL: entrez_ssl.apply_entrez_ssl_settings() before Entrez calls
    - LIT_REVIEW_ENTREZ_INSECURE_SSL=1 on inspected networks (GUI checkbox)
    - Or LIT_REVIEW_SSL_CA_BUNDLE / certifi
  - Always re-fetches PubMed on refresh (new input.ris per run)

STAGE 2 — V4 full-text scrape (full_text_scrape_V4.run_full_text_scrape)
  - Input: run.input_ris
  - Selenium browser automation per reference
  - PDF storage modes (env-driven):
      LIT_REVIEW_PDF_REMOTE (preferred): rclone copy to gdrive:.../pdfs
        — no FUSE mount; works on macOS 26+
      LIT_REVIEW_PDF_STORE (legacy): local FUSE-mounted folder + symlinks
  - Content-addressable filenames: pmid_<id>.pdf, doi_<hash>.pdf, title_<hash>.pdf
  - SKIP existing PDFs (do not re-download):
      1. build_cas_index / build_remote_index on Drive pdfs/
      2. build_master_pdf_skip_keys on newest pubmed_*.txt in RIS_source_files
         (records with L1/L2/L3 attachment paths)
  - Per-record progress.jsonl (append immediately) — powers --resume
  - On completion: found/found.ris, missing/still_missing.ris, summary counts
  - found.ris is written ONLY at end of V4 loop (not incrementally)

STAGE 3 — Post-scrape chain (_run_post_scrape_chain in auto_search_wrapper.py)
  Step 1: convert_ris_to_absolute_paths(found.ris)
  Step 2: add_research_notes_to_ris_with_explicit_label(..., metadata.search_term_label)
          — writes RN field verbatim; this becomes visualizer branch_terms
  Step 3: merge_ris_to_master(step2_output, RIS_source_files/)
          — O(N) dedupe by DOI/PMID/normalized title
          — Creates NEW file pubmed_NLP_v4_<timestamp>.txt (never overwrites in place)
          — Uses .cache/master_lookup.json keyed by master mtime
  Step 4: save_metadata(finished_at=...), write_summary.md
  Step 5: sync_run_to_r2 (unless LIT_REVIEW_AUTO_R2_SYNC=0)

STAGE 6 — Visualizer consumption (separate process)
  - config.get_queries_with_ris_files() picks newest file per prefix (e.g. pubmed)
  - Papers parsed; RN → branch_terms; grouped under query nodes
  - Deployed site needs git push of new RIS + R2 already synced
  - Local reload: GET /api/reload or restart Flask


6. CATALOG ↔ PIPELINE ↔ VISUALIZER CONTRACT
-------------------------------------------

COMMON_SEARCH_TERMS in visualizer_nlp_lit_review/config.py is the single
catalog. Each automated entry MUST have all three:
  - query   : PubMed query string
  - slug    : normalized run-folder suffix (e.g. nlp_extraction)
  - label   : exact string written to RIS RN field (e.g. "( NLP extraction )")

refresh_catalog.py and admin_gui.py both load this dict via importlib.
The visualizer query name (dict key, e.g. "NLP_Extraction") is separate from
slug/label but should stay semantically aligned.

Mapping to visualizer tree:
  Query node  ← config key / prefix-resolved master RIS
  Branch node ← each distinct RN / branch_term on papers under that query

When adding a new live search: update config.py FIRST, then run wrapper or
refresh_catalog. Commit new pubmed_*.txt under RIS_source_files/ for deploy.


7. RUN FOLDER CONTRACT (automated_search/SCHEMA.md)
---------------------------------------------------

run_id = YYYY_MM_DD_HHMMSS__<slug>[-N]

Tracked in git:     metadata.json, summary.md
Gitignored:         input.ris, found/*, missing/*, progress.jsonl, errors.jsonl, log.txt

metadata.json:
  - Validated by search_run._validate_metadata — DO NOT add fields without
    updating SCHEMA.md, validator, and tests/test_metadata_schema.py
  - MUST be written only via save_metadata() (atomic .tmp + os.replace)
  - search_term_label is used verbatim for RN stamping

progress.jsonl:
  - One JSON object per line per attempted record
  - --resume skips success, skipped_existing, and terminal error_reasons

Agents: treat SCHEMA.md as authoritative; grep search_run.py for enforcement.


8. PDF STORE & DEDUPLICATION
----------------------------

CAS key priority: pmid → doi (normalized hash) → title (normalized hash)

ensure_pdf_store.py centralizes:
  - resolve_pdf_store / remote index via rclone lsf
  - cas_key_for_reference, pdf_already_on_file
  - build_master_pdf_skip_keys (master RIS L1/L2/L3)
  - upload_pdf_to_remote (rclone copy)

Design intent: Refresh Catalog always re-queries PubMed but must NOT waste
time re-downloading PDFs already on Drive or already attached in master RIS.

If changing skip logic: update V4 startup counts AND log lines; add tests in
automated_search/tests/ where feasible.


9. ENVIRONMENT VARIABLES (REFERENCE)
------------------------------------

Required for typical run:
  NCBI_EMAIL              — NCBI ToS contact
  LIT_REVIEW_PDF_REMOTE   — e.g. gdrive:nlp_lit_review_1_papers/pdfs
    OR LIT_REVIEW_PDF_STORE — absolute mount path (legacy)

Recommended:
  NCBI_API_KEY            — higher Entrez rate limits

Optional:
  LIT_REVIEW_R2_REMOTE, LIT_REVIEW_GDRIVE_REMOTE — R2 sync overrides
  LIT_REVIEW_AUTO_R2_SYNC=0 — skip end-of-run R2 sync
  LIT_REVIEW_ENTREZ_INSECURE_SSL=1 — hospital SSL inspection (use sparingly)
  LIT_REVIEW_SSL_CA_BUNDLE — institutional CA PEM
  ADMIN_ENABLED=true — Flask admin routes (local only)
  PYTHONUNBUFFERED=1 — real-time logs in GUI/subprocess

rclone remotes gdrive: and r2: must be configured on the machine running the pipeline.


10. PROJECT CONVENTIONS (MANDATORY FOR AGENTS)
----------------------------------------------

Python scripts:
  - Top-of-file comment block: INPUT files/dirs and OUTPUT files/dirs
  - Generated outputs: header comment naming generating script

Analysis / versioned outputs (repo-wide user rule):
  - If output file exists (same base name ignoring v# suffix), move old file to
    archive/ subfolder at same level, then write new file with v# suffix

Git safety:
  - automated_search/searches/* large artifacts are gitignored except metadata/summary
  - DO commit new master RIS in visualizer_nlp_lit_review/RIS_source_files/ after
    successful merges intended for production

Do NOT:
  - Write metadata.json directly (bypass save_metadata)
  - Break schema_version without migration plan
  - Enable ADMIN_ENABLED on production Render
  - Hardcode absolute OneDrive paths in new code (legacy fallback only)
  - Reintroduce per-paper rglob over entire download trees (use CAS index)
  - Set LIT_REVIEW_ENTREZ_INSECURE_SSL by default in committed code

12. INTERRUPTION, STOP, AND PARTIAL STATE
---------------------------------------

admin_gui Stop → killpg(SIGTERM) on wrapper or refresh_catalog process group.

If stopped mid-V4:
  - PDFs already uploaded to Drive: KEPT
  - progress.jsonl: partial audit trail
  - found.ris: often MISSING (written at V4 end)
  - master RIS: NOT updated (merge is post-V4)
  - visualizer: unchanged until new merge + deploy/reload

Resume: auto_search_wrapper.py --resume <run_folder>

refresh_catalog: stops current wrapper; does not auto-resume prior partial runs;
  completed catalog entries before stop will have merged.

17. TROUBLESHOOTING CHEAT SHEET
-------------------------------

PdfStoreUnavailable → set LIT_REVIEW_PDF_REMOTE or fix rclone
Entrez SSL errors → LIT_REVIEW_ENTREZ_INSECURE_SSL or CA bundle
ModuleNotFoundError Bio → pip install biopython
Empty GUI log during refresh → ensure PYTHONUNBUFFERED / python -u (already in refresh_catalog)
Visualizer shows old data → merge didn't finish OR need /api/reload OR redeploy
R2 out of sync → sync_pdfs_to_r2.py --run <run>
